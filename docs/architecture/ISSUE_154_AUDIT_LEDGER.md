## Recorded limitations (not introduced by this slice)

**A compiler defect during validation escapes unclassified.** `_validate_processes` calls the
effect resolver and then, for every root, the semantic validator; neither call is inside a guard.
A failure to snapshot or lower is by policy a COMPILER defect that must escape rather than become a
report entry, and the compiler's own guarded boundary lives in its compile entry — which this
function does not go through. Measured while reconciling `CDX-154-r14-01`: driving a preparation
failure through the validator directly raises the raw exception, on the path a caller takes when
declaring nothing at all. So a caller hitting a compiler bug during PLANNING receives an
unclassified error rather than the value-free causal diagnostic the compile path produces.

This predates the slice and is general to that function; the effect resolver neither causes it nor
widens it, and is simply the first statement to touch a child. It is recorded rather than fixed
because translating it inside the resolver would have the resolver classify compiler defects — the
authority boundary evaluation 13 established it must not cross — and would leave the identical
escape one statement later. No issue is minted: it blocks nothing here, and the repository's rule
is to record an accepted limitation rather than mint debt.

* **~~No `map_ref` compiles through the public authoring path at all.~~ — THIS CLAIM WAS FALSE and
  is corrected here** (raised by the §6 architect review; see `CDX-S6-07`). What is true is
  narrower: the BRACKETED `connector_call` form is blocked, because `build_symbol_table` never sets
  `input_profile_ref`/`output_profile_ref` and the call-pair check treats an absent profile as a
  mismatch. The LEGACY `source -> map_ref -> return_documents` form deliberately bypasses call-pair
  profile checking and COMPILES — measured. The original claim generalised from one topology to
  "the public path", and QA's reachability rationale tested that same wrong topology, so nothing

  now drives one through resolve -> compile -> emit with a control. `script_effects` remains without
  one, because the vetted registry ships deliberately empty — that half of the original statement
  stands.
* **A literal existing-profile UUID is index-resolved when the plan can resolve it.** *(Corrected
  2026-08-24 when #179 was absorbed into this slice — the limitation as written no longer holds, and
  a deferral record is kept true like served text.)* `literal_indexes` is now threaded from the
  authoring workflow, which reuses the integration builder's own resolver with the client it already
  holds at plan time. For a map whose endpoints the plan can resolve, the question is ANSWERED: both
  masked classes are closed — the checks ordered after the lookup, and the index-CONDITIONAL ones the
  authority skips when the index is `None`.

  What remains deferred is strictly narrower: an endpoint that nothing available can resolve — no
  client, or a UUID absent from both the caller's map and live discovery. That map still derives, and
  every other refusal still makes it opaque. The scope is decided by whether an index was SUPPLIED
  for the map's own endpoints, NOT by the refusal's detail set: measurement showed the no-index and
  the index-TYPE-MISMATCH branches both report exactly `{"side"}`, so the criterion #179 itself
  proposed would have kept deferring a fully decidable refusal — the very defect that issue warned
  its own fix could mint.

  **The masking has two mechanisms, not one.** The plan authority returns the index refusal early, so
  checks ordered AFTER it are not reached (`document_cache_joins`). It also skips path-existence
  checks when the index is `None`, so index-CONDITIONAL checks ordered BEFORE it are masked as well —
  measured: literal UUIDs plus a `source_path` absent from the profile derives a trusted effect while
  the plan refuses with its field-not-found code. Both are enumerated in #179; this entry is that
  enumeration's in-tree twin and is kept equal to it.

  **Stated falsifier**, adopted from the round-7 analysis: the entire gate-vs-plan divergence surface
  is now exactly this one argument. If a later round finds a divergence that is NOT `literal_indexes`,
  the premise is wrong and the right move becomes narrowing what a map declaration may claim at all,
