## Design decisions recorded during implementation

| # | Decision | Why |
| --- | --- | --- |
| D1 | No `connector_action.wss.listen` entry is served (the architect plan asked for one) | That entry type is served as "a callable connector family/action pair; the registry is a closed allowlist". A WSS Listen operation is NOT callable, so publishing it under that type would make the served type definition false. Its family and action are served by `node.listener`, `capability.listener_entry` and the `semantic_rule.listener.*` entries instead, and the connector-action refusal's cited diagnostic entry names the listener node's selector. Revised after QA-158-r1-01: the first version of this justification rested on `GATED_CONNECTOR_CALL_REASONS`, a table nothing serves, and was measured false. |
| D2 | The pre-flip capture script is committed as a `.py` file in the evidence archive (the implementation plan preferred text) | It is the exact invocation that produced the bytes; issue-155 set the precedent of a script in the archive, and every scanner passes with it. |
| D3 | The legacy process-flow `$ref` role check is unchanged | It already routes on the WSS builder's own resolver; the canonical counterpart of the WSS operation-only `$ref` dispatch is the compiler's listener-entry resolution (`validate_listener_entry`). |
| D4 | The reused-listener confirmation runs on a REAL run only | A dry run reads nothing from the account by contract. The check fails closed: a reused listener whose start cannot be read, or starts on another operation, refuses before any package exists (`BUILD_LISTENER_ENTRY_MISMATCH`). |
| D5 | The execution profile no longer consults any symbol | The entry node alone decides. The five #153 revision witnesses keep their node ids and are rewritten onto the new authority: symbol-driven mutants must move the served revision, faithful reimplementations must not, and the table-size whitelist moves to the one family lookup left on this path, the listener entry's `listener_operation_symbol`. |
| D6 | A submitted raw WSS operation XML with no Listen element is now refused | The WSS family's verb location is measured (the element's presence), so a WSS document naming no action settles nothing — the same rule every other known-verb family already has. A served behaviour change, covered by live QA. |
| D7 | The compile-path parse-code allowance retires `PROCESS_IR_SCHEMA_INVALID_CARDINALITY` | The compiler now emits it statically (listener position), which is exactly the case the allowance's stale-entry check requires retiring. |
