## What was changed from the original delivery

All changes are to the source project's references and to account ids hard-coded in tooling. The algorithm code is unchanged.

- **Private corpus.** `lab/evaluate.py` and `tests/test_autoformat.py` dropped the second corpus: 61 arranged processes and 11 caller-layout pairs.
  - It lived only on the original author's machine, in another project, and was never shipped.
  - Its path, process names, known-stale-value exception and the two tests that read it are gone.
  - In the original, `test_known_stale_boomi_value_is_the_only_exception` failed wherever that corpus was absent.
- **Docs.** `README.md`, `boomi_autoformat/README.md`, `docs/arrange_rules.md` and `docs/arrange_observations.md` now:
  - state the evidence as the 35 reproducible lab pairs;
  - no longer claim coverage of connector, map, data process, cache or route shapes, which rested only on the private corpus;
  - name the demo account through this file, not inline.
- **`lab/page_helper.js`** takes the account id from `window.aflAccountId` instead of a hard-coded literal.
- **`lab/generate.py`** takes the folder id and the two child-process ids from environment variables (`AFL_FOLDER_ID`, `AFL_CHILD_WITH_RETURN`, `AFL_CHILD_RETURN_SHAPE`, `AFL_CHILD_NO_RETURN`) instead of literals.

`SHA256SUMS` covers every file in this directory except itself.

## Known caveats the implementing issue must carry

These come from a Codex plan review on 2026-10-20.

- **One Arrange, not a fixed point.** Unset dragpoints keep their pre-Arrange height, so a second Arrange moves them again (p09). This happens in Boomi as well as in the emulator. The suite's idempotence test deliberately excludes them.
- **Shape types without recorded evidence.** `connectoraction`, `map`, `dataprocess`, `doccacheload`, `doccacheremove` and `doccacheretrieve`, plus connector/listener Start variants.
  - The y offset `−trunc((rendered height mod 16) / 2)` depends on the rendered widget height.
  - Record UI-arranged captures before trusting the emulator for those types.
- **Attribute decoding.** `xmlpatch._attr_value` decodes with `html.unescape`, which is HTML rules, not XML: `&#x80;` becomes `€` where XML gives `\x80`.
  - A shape whose name uses such a reference is looked up under the wrong name, and its coordinates are silently left unchanged.
  - Fix this when vendoring, and assert that every modeled target was patched.
- **Coordinates and canvas selection.**
  - `model.parse` accepts non-finite coordinates.
  - It selects the first `process/shapes` in document order. The server should select the component canvas by path.
