### Pre-committed stopping rule for the evidence archiver (recorded BEFORE the round it governs)

Rounds 5, 6 and 7 of the Stage-2 loop all landed on one artifact — the archiver this slice had to
write because no producer for the archive index existed — and nothing they found reaches a served
surface. That artifact is FINITE; the space of malformed attestations, mis-supplied paths and
foreign index shapes it could be asked to survive is UNBOUNDED. This repository has twice recorded
what that costs: a finite artifact bound to an unbounded space does not converge, and the rounds
keep finding correct defects until someone states a rule. Stated here before round 8 opens, so it
is a rule and not a rationalisation of whatever that round returns.

From round 8, each archiver finding is judged into exactly one bucket at reconciliation:

1. It can damage something this slice does not own — another issue's archive, a committed record, a
   gate's evidence, the tree. FIX IT, and note that its blocking class is mutation accounting, which
   derives critical on its own anchor and is therefore never deferrable. Round 7's re-derivation
   finding and the self-recorded verdict-erasure are both this bucket.
2. It lets the archiver accept evidence that is WRONG — a wrong prompt, an unattested round, a null
   digest where a real one exists, a completion the collector declined to record. FIX IT. This is
   the artifact's entire purpose; an archiver that accepts bad evidence is not unhardened, it is
   broken. Rounds 5 and 6 were this bucket.
3. It makes the archiver crash or misbehave on input NO producer emits. RECORD A BOUNDARY VERDICT:
   name the input, name the producer that would have to emit it, and stop. These earn a row and a
   disposition, not a code change. The archiver's inputs come from two known collectors and from
   this script itself, and a defect in what those emit is a defect in them.

Round 7's non-string-digest finding sits on the 2/3 line and was fixed rather than verdicted only
because the fix was one clause of what bucket 1 already required. A standalone successor of that
shape is bucket 3. This rule bounds which findings earn a CODE change and relaxes nothing else: not
owed validation, not the undeferrability of a critical finding, not the wave gate's currency on the
final tree, and not the recording rules — every finding still gets a row and exactly one
disposition.

### Archiver FREEZE, declared before round 13 (recorded 2026-08-27)

The stopping rule above bounded which findings earn a code change. It was not enough, and the
measurement says so plainly. Rounds 5 through 12 — EIGHT consecutive Stage-2 evaluations, seventeen
findings — landed entirely on the evidence archiver. Not one reached a served surface; slice A's
functional code has returned clean since round 4. Across those rounds I introduced a regression or
reintroduced a closed defect class into that artifact repeatedly, and round 12 recorded the
check-after-mutate shape arriving for the THIRD time, twice after a structural fix meant to end it.

Three structural fixes each did end their own line of findings — deriving the row from the consuming
authority, publishing the round by an atomic move, bounding the names the manifest can record. New
lines kept opening. That is not a converging loop, and the honest reading is that continuing to
harden this artifact inside this slice costs more than it protects.

**So the archiver is FROZEN for slice A from round 13.** The artifact has done its job: twelve rounds
are archived, the index is derived and verified, and the repository's own scanners pass on it. From
here a STANDARD-tier finding against it gets a row, a disposition and a boundary verdict naming the
mechanism, and is surfaced to the owner as residue rather than fixed.

**Corrected at its first application (round 13).** As first written this rule said a code change
required a finding to be BOTH critical AND reachable through the invocation this loop actually
makes. That is wrong, and applying it once was enough to show why: the completion workflow states
that a critical finding is never deferrable — fix and validate, or escalate with the issue open —
and a local scope decision of mine cannot override the governing rule. A freeze that would have
boundary-verdicted a critical finding was not a stricter rule, it was an unauthorised waiver.

So the freeze binds STANDARD residue only. A critical finding against this artifact is still fixed
and validated, however narrow its trigger, or the issue escalates open. Round 13's finding is
exactly that case: labelled P1 by its gate, in the mutation-accounting class, and therefore critical
by two independent anchors — so it was fixed, and the freeze did not and could not excuse it. What
the freeze still does is stop the loop spending itself on the standard-tier hardening that consumed
rounds 5 through 12. Recorded here rather than quietly re-scoped, because a rule corrected on
contact with the case it was written for should say so.

This is a decision about SCOPE, not about validation. It relaxes nothing: the round-12 correction
still owes its affected QA and its delta-scoped review, a critical finding remains undeferrable,
the wave gate must still be current on the final tree, and every finding still gets exactly one
recorded disposition. What it stops is the loop treating a self-owned tool as though it were the
product. The residue is real and is recorded as such; filing it is the owner's to authorise, and
this loop does not file.
